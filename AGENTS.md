# Community guidance

- Keep shared guidance applicable across repositories; link to the owning repository for setup and behavior.
- Keep credentials, private implementation details, and links to private repositories out of public documents.
- Use Conventional Commits with scope `repo`.

## Documentation

- READMEs cover overview, prerequisites, quick start, common commands, and links. Update them only for these changes; keep tool and dependency versions in repository configuration.
- Update docs only when requested or when a change makes directly relevant guidance inaccurate or materially incomplete. A code change alone does not require a documentation update.
- Keep repository-specific architecture, implementation, workflow, and deployment guidance in the owning repository's `docs/`. Keep community documents focused on shared guidance; do not append task summaries or unrelated technical notes.
